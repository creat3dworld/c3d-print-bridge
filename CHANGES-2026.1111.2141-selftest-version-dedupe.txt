- (1) Self-test version check (SelfTest.cs,
  CheckSlicerAsync): an unreadable file version no longer
  fails the check. If FileVersionInfo returns empty or
  throws, the check proceeds to the runnable test (start
  the exe hidden, watch 5 seconds) and the detail says
  the version is "unknown (file version unreadable)".
  The runnable test is the authority: a slicer that
  starts passes; a missing exe, or one that cannot be
  started, still fails exactly as before. This stops the
  ongoing OrcaSlicer version errors on both PCs.
- (2) SlicerSetup subfolder candidates (SlicerSetup.cs,
  FindSlicerExe): a no-space folder name is now tried when
  resolving a slicer under the dashboard default location
  - BambuStudio, SnapmakerOrca, OrcaSlicer - in addition
  to the existing direct, slicer-word, and display-name
  ("Bambu Studio" / "Snapmaker Orca" / "OrcaSlicer")
  candidates. "OrcaSlicer" repeats its display-name
  candidate (one extra File.Exists call, no behaviour
  change). A working local path is still never
  overwritten; discovery only fills a gap.
- (3) Self-test reporting dedupe (SelfTest.cs, RunAsync):
  each check now has a per-check dedupe key
  ("check|printer_ip") with report-on-transition. A
  failing check reports an error only when it TRANSITIONS
  into fail; a check that keeps failing does not re-report
  on every self-test run (startup, reconnect,
  machine-config change) - the dashboard already has the
  alert. A recovery (pass/skip) clears the entry, so a
  later re-failure reports again. The self-test REPORT
  itself is still sent on every run; only the duplicate
  error reports are suppressed. In-memory only: a bridge
  restart re-reports a still-failing check once (one fresh
  alert per restart, not one per self-test run). The
  ErrorReporter 15-minute throttle is unchanged and still
  applies underneath. No new error type, no change to the
  error-reporting channel, no wire name renamed.
